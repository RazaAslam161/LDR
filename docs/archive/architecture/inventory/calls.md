(5) Re-arming after a socket drop is owned by `AppShell`, which is unmounted whenever the disguise cover is up.
- scale reason: The topic is an unauthenticated, guessable-by-UUID public broadcast room; call teardown and call injection are available to anyone who can enumerate or obtain a couple id. Beyond security, the design needs both apps foregrounded and unlocked-past-the-cover with a live websocket to work at all — the realtime path is best-effort at every hop, and the couple-scoped topic means no multi-device story exists.

## Push ring delivery (`reach-notify` edge function → FCM)  [risk: fatal]
- purpose: Turns a `call_invites` insert into a high-priority FCM data message on the callee's device so a backgrounded or killed app can ring.
- files: E:/LDR/supabase/functions/reach-notify/index.ts (shared by reach / care / call / message)

(4) `profiles.fcm_token` is a single scalar column — one device per user, by construction. A reinstall or a second phone silently steals the ring. (5) `display_name` is sent in cleartext as `from_name` and lands in a notification on a device whose whole product premise is a disguised launcher.

- transport: Neither — pure local state from `CallController` (a ChangeNotifier) plus `pc.getStats()` polling.
- how it works: AppShell holds `_lastCallState` and pushes `/call` on the inactive→active transition (idle/ended → ringing/calling/connected). `CallScreen` pops itself when state returns to `idle`, showing `takeLastError()` in a 5s SnackBar first (the one-shot error channel; `_readableCallError` maps permission/device errors to sentences). Back-gesture minimises rather than hangs up (`PopScope` + `setMinimized(true)`). The remote `RTCVideoView` is only mounted when `connected && video`; the local preview mirrors on `call.frontCamera` (driven by `Helper.switchCamera`'s return value, which reports whether the NEW camera is front-facing) and uses `FilterQuality.medium` for the downscale. A long-press anywhere toggles `_showStats`, a `ValueNotifier` deliberately declared outside the widget so it survives minimise/reopen. `CallStatsMonitor` polls `pc.getStats()` every 2s from `_createPc` onward (not from connect), indexes the report graph by id, resolves the SELECTED candidate pair via `transport.selectedCandidatePairId` (falling back to nominated+succeeded), and reports tx/rx resolution+fps+kbps, `qualityLimitationReason`, RTT, packets lost, relay-vs-p2p, and the negotiated codec — `debugPrint`ed on every sample. A red banner warns when `relayKnown == false` during calling/ringing.
- weaknesses: (1) No call duration timer anywhere in the UI. (2) The pill shows for `connected` or `calling` but NOT `ringing`, so a minimised incoming call has no visible affordance. (3) The `/call` push depends on `ref.listen` observing a transition — a state that changed before AppShell mounted (cold start, or return from the disguise cover) produces no navigation. (4) Every stats sample is `debugPrint`ed unconditionally, including in release-mode logcat. (5) The overlay and the NO-RELAY banner are the only diagnostics and they are on-device only — nothing is reported anywhere a developer could see it at scale.
- scale reason: Client-side rendering only, no backend cost. The gap that matters at scale is observability: the stats exist but never leave the device, so field failures remain anecdotes.
