## How it works (data-only push)

The push is a **data-only** FCM v1 message. On Android, data-only lets *our*
background handler build the notification on `reach_channel` with the
full-screen intent — notification-only messages are drawn by the OS and won't
reliably wake the screen on our channel.

```
A taps Reach → insert reach_events → AFTER INSERT trigger (pg_net.http_post)
  → reach-notify Edge Function:
      • recipient = other profile in couple (profiles.couple_id)
      • mint OAuth2 token (service-account RS256 JWT → Google token endpoint)
      • POST fcm/v1/projects/<id>/messages:send  { data:{type:reach,from_name,...} }
  → B's device:
      • foreground → in-app ReachOverlay (de-duped vs the realtime listener by reach_id)
      • background/terminated → background isolate shows reach_channel notification
            fullScreenIntent = (cached FSI permission)  ← wakes a locked screen if granted
      • tap → app opens → ReachOverlay → "I'm here 💕" sets acknowledged_at
```

## Android 14 full-screen-intent caveat
Tethered does **not** auto-qualify for `USE_FULL_SCREEN_INTENT` (it's not a
calls/alarm app). On Android 14+ the user must grant it; we **request** it
(one-time prompt + Settings tile) and **degrade gracefully** to a max-priority
heads-up notification when it's not granted — never a crash. The background
isolate can't query the permission live (no Activity), so the foreground caches
it to `SharedPreferences('fsi_can_use')` for the handler to read.
**Play Console:** declare the `USE_FULL_SCREEN_INTENT` permission at submission
(person-to-person "reach" is an allowed use).

## iOS notes (Phase 6 — when you build for iOS)
- Xcode: enable **Push Notifications** + **Background Modes → Remote notifications**.
- Upload the **APNs `.p8`** auth key → Firebase console → Cloud Messaging → Apple config.
- **Limitation:** iOS can't force-wake a locked screen like Android's FSI. The
  reach arrives as a high-priority banner + sound. A louder "critical alert"
  needs a special Apple entitlement (request + approval) — future, non-blocking.

## Security note
`reach-notify` is deployed with `verify_jwt=false` (a server-side DB trigger is
the only caller). It performs no privileged action beyond sending a benign push
and requires real `couple_id`/`from_user` UUIDs. To harden later, add a shared
secret header checked in the function.
